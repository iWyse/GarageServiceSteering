# ГУРсервис — учёт клиентов, записей и расходников автосервиса

Веб-приложение для одного автосервиса: расписание записей, база клиентов с историей ремонта,
очередь заказов на запчасти, заказ-наряды, справочник расходников, личные заметки владельца и
личный кабинет для клиентов (вход по VIN). Рассчитано на одного владельца/администратора
(авторизация по логину и паролю), крутится на локальном сервере без внешних зависимостей.
Полностью адаптировано под мобильный экран — и админка, и кабинет клиента.

## В двух словах

- **Расписание** — неделя, дни Пн–Сб, drag-and-drop записей, разовые визиты без базы.
- **Отчёт** — список выполненных работ по автомобилям за выбранную неделю (дата, тег клиента,
  автомобиль, сумма работ, сумма запчастей + итоговая строка), с тем же фильтром по неделям, что
  и в расписании. Строка кликабельна — открывает саму запись ремонта.
- **Клиенты** — карточка с тегом для поиска, кликабельный телефон, копирование VIN одной
  кнопкой, поиск по имени/телефону/номеру авто/VIN, колонка с датой последнего редактирования,
  сортировка списка (по имени / по алфавиту машин / по дате правки в обе стороны), история
  ремонта.
- **История ремонта / смета** — запчасти в одну строку-таблицу (галочка «включить», название,
  цена, кол-во, фирма, артикул, крестик — колонки выровнены как в настоящей таблице, подписи
  сверху), копирование артикула одной кнопкой, срок поставки, аванс. Дата записи необязательна
  (по умолчанию не проставляется — можно сохранить и без неё, в истории такая запись подписана
  «Без даты»). Кол-во у запчасти — информационное поле, на сумму не влияет (цена в строке — это
  цена всей позиции, а не цена за штуку). У запчасти можно добавить **аналоги** — несколько
  вариантов одной и той же позиции (например, три амортизатора разных фирм) на выбор клиента; в
  сумму и в заказ-наряд попадает только выбранный вариант, остальные видны как альтернатива с
  пометкой «аналог». У каждой позиции есть **галочка «включить»** — снятая позиция остаётся в
  сохранённой смете, но не попадает ни в сумму, ни в заказ-наряд, ни в историю, ни в отчёт
  (клиент из всего списка решил отремонтировать не всё).
- **Смета из расписания** — кнопка на записи ищет клиента по имени и предлагает дополнить
  существующий ремонт или создать новый; для разового визита клиент заводится автоматически.
- **Заказ-наряд** — оформленный документ (шапка с реквизитами, запчасти/работы с датой ремонта,
  рекомендации), открывается на весь экран на телефоне. Три способа отправить клиенту:
  «Копировать картинку» (PNG с `<canvas>` в масштабе ×3 — сразу в буфер обмена, вставить в
  мессенджер), «Скачать картинку файлом» (тем же PNG, но файлом — мессенджеры не пережимают
  документы, качество сохраняется) и «Скачать A4 (PDF)» — печатная светлая версия через
  системный диалог печати браузера (`@media print`), почти любой заказ помещается на одну
  страницу A4.
- **Заказы** («в очереди») — клиенты, которым заказаны запчасти. У каждой запчасти (под общей
  строкой-таблицей) свой флаг «на складе» и выбор поставщика (АТС / ПЛ / emex / Микадо); общий
  статус заказа («в ожидании» / «запчасти пришли») считается автоматически по этим флагам, пока
  в заказе есть хоть одна запчасть. Дата заказа необязательна и не проставляется сама. Нового
  клиента для заказа можно подтянуть из базы вместо ручного ввода; поля клиента и машины спрятаны
  в аккордеон, чтобы сразу были видны запчасти/работы. В общую базу клиентов заказ попадает
  только по кнопке «Добавить в список клиентов».
- **Расходники** — двухуровневая структура: разделы → категории → позиции с артикулами
  (копирование одной кнопкой) для регулярно заказываемых материалов.
- **Заметки** — свободные личные заметки владельца, отдельная вкладка. Можно пометить заметку
  «срочной» — такие всегда идут первыми в списке.
- **Кабинет клиента** — отдельный вход по VIN автомобиля (см. ниже). Клиент видит и сам
  дополняет данные своей машины (имя, телефон, марка/модель, гос. номер, заметки), может
  поправить опечатку в собственном VIN, видит историю выполненных работ (только чтение) и может
  отправить заявку в сервис — текст и/или фото. Данные машины синхронизированы с админкой:
  правки админа сразу видны клиенту (приоритет у данных из базы), а заметки идут в обе стороны
  отдельными полями — клиент видит блок «Заметка сервиса», админ в карточке клиента видит блок
  «Добавил клиент» (выделен оранжевым). Если VIN ещё не заведён в базе, кабинет работает как
  форма регистрации: имя/телефон/марка/модель обязательны, кнопка называется «Добавить в базу»,
  а админу автоматически приходит заявка о новом клиенте.
- **Заявки** — входящие сообщения из кабинета клиента, отдельная вкладка у владельца с бейджем
  непрочитанных. Если VIN не найден среди клиентов, карточка заявки предлагает кнопку
  «Добавить клиента» — она открывает диалог нового клиента с уже подставленными VIN и всеми
  данными, которые клиент успел ввести в своём кабинете (даже если он не нажимал отдельную
  кнопку «Сохранить» — анкета сохраняется автоматически при отправке заявки).
- Счётчики (бейджи) у вкладок «Заказы», «Заявки», «Заметки» — количество записей/непрочитанных.
- Строгие маски ввода: телефон — только цифры, всегда с `+7` (в логине владельца `+7`
  подставляется сам при фокусе); марка/модель — английские буквы и цифры в верхнем регистре;
  гос. номер — формат `Б999ББ999` (буква-цифры-2 буквы-цифры), буквы только из набора,
  разрешённого ГОСТом для рос. знаков, с автозаменой похожих латинских букв на кириллические;
  VIN при входе в кабинет клиента — английские буквы, цифры и дефис, с автозаменой похожих
  кириллических букв на латинские.
- Подтверждения удаления и закрытия окна кликом мимо — свой стилизованный диалог, не системный
  `window.confirm`. Клавиша **Escape** закрывает открытое окно (самое верхнее, если их
  несколько) мгновенно, без подтверждения — либо мобильное меню, если открыто оно. **Enter**
  в многострочном поле сохраняет форму и снимает фокус, **Shift+Enter** — перенос строки.
- Мобильная версия — полноэкранные диалоговые окна, вкладки собраны за иконкой-гамбургером,
  громоздкие блоки полей спрятаны в аккордеоны (данные клиента в заказе, кнопки добавления
  расходника), кнопка «Выйти» сокращена до иконки.
- Лёгкие анимации появления окон, тостов, вкладок и аккордеонов (уважают
  `prefers-reduced-motion`).
- Всё в одном общем аккаунте — данные видит и правит один и тот же авторизованный владелец.

## Стек

- **Backend:** Node.js (встроенный `http`, без Express) + встроенный `node:sqlite` — **нет ни
  одной внешней npm-зависимости**, `npm install` не нужен.
- **Frontend:** обычные HTML/CSS/JS, без сборщиков и фреймворков (единственный внешний ресурс —
  шрифты Google Fonts по CDN).
- **Требование:** Node.js **22.5+** (нужен для `node:sqlite`). Проверить версию: `node --version`.

## Запуск локально

Сначала задайте логин/пароль владельца — скопируйте `.env.example` в `.env` и впишите свои
значения:

```bash
cp .env.example .env
```

```
OWNER_PHONE=+70000000000
OWNER_PASSWORD=ваш-пароль
```

Затем запустите сервер:

```bash
node server.js
```

Откройте http://localhost:3000 — сайт сразу покажет экран входа. Без `.env` (или без обеих
переменных в нём) сервер не запустится и сразу подскажет, что нужно исправить.

При первом запуске автоматически создастся файл `autoservice.db` (SQLite) со всеми таблицами —
ничего дополнительно настраивать не нужно. При обновлении версии приложения на уже существующей
базе миграции колонок/таблиц применяются автоматически при старте сервера.

Порт можно поменять переменной окружения:

```bash
PORT=8080 node server.js
```

## Авторизация

Два независимых входа с отдельными cookie-сессиями (`HttpOnly`, `SameSite=Lax`, 30 дней). Сессии
кешируются в памяти процесса для быстрой проверки на каждый запрос, но зеркалятся в таблицу
`sessions` в БД — перезапуск сервера (деплой, обновление) не разлогинивает пользователей, пока
cookie в браузере остаётся валидной; записи старше 30 дней подчищаются автоматически при старте.

- **Владелец** — телефон + пароль, заданы переменными окружения `OWNER_PHONE`/`OWNER_PASSWORD`
  (файл `.env`, в git не попадает — см. «Запуск локально»). Без входа всё API, кроме путей ниже,
  отдаёт 401, фронтенд показывает форму входа.
- **Клиент** — вход только по VIN автомобиля (до 17 символов):
  - если VIN найден среди клиентов — вход сразу успешен;
  - если не найден — просит пароль, чтобы отсечь спам-ботов. Пароль равен текущему году
    (считается на сервере функцией `currentYearPassword()`, автоматически меняется 1 января).
  - После входа клиент видит только свой кабинет (`/api/client/*`), не владельческие данные.

Пути `/api/login`, `/api/logout`, `/api/session`, `/api/client-login`, `/api/client-logout`,
`/api/client-session` не требуют авторизации (это и есть вход). `/api/client/*` проверяют
клиентскую сессию (не владельческую) — своя, более узкая проверка прямо в обработчике каждого
пути. Всё остальное API закрыто владельческой сессией и без неё отдаёт 401.

## Основные сущности

- **clients** — клиенты: имя, телефон, марка/модель, гос. номер, тег, VIN, заметки, дата
  последнего редактирования (`updated_at` — по ней сортировка списка).
- **appointments** — записи в расписании; либо привязаны к клиенту (`client_id`), либо это
  разовый визит (поля `walkin_*`), который в базу клиентов не попадает.
- **repair_records** — история ремонта клиента: заголовок, дата (не обязательна — по умолчанию
  пустая строка, а не `NULL`, схема осталась `NOT NULL`), работы/запчасти (JSON:
  `[{name, price, article?, brand?, qty?, analogGroup?, analogSelected?, included?}]`), срок
  поставки запчастей, аванс, рекомендации. `analogGroup`/`analogSelected` — необязательные поля
  для группы аналогов одной позиции; `included: false` — позиция, которую клиент решил не делать
  (отсутствие поля равносильно `true`, см. «В двух словах» выше).
- **queue_entries** — заказы «в очереди»: те же поля, что у клиента, плюс смета и статус
  (`waiting` / `arrived` — на фронтенде пересчитывается автоматически по запчастям, если они
  есть). У запчастей в JSON дополнительно `received` (флаг «на складе») и `supplier`
  (АТС/ПЛ/emex/Микадо) — эти два поля используются только на странице заказов. Превращаются
  в настоящего клиента вручную, кнопкой «Добавить в список клиентов».
- **consumable_sections** → **consumable_categories** → **consumables** — двухуровневая
  структура расходников (раздел → категория → позиция с артикулом); категория может быть без
  раздела, расходник может быть без категории — пользователь заводит всё сам, ничего не
  предустановлено.
- **client_car_profiles** — анкета, которую клиент сам заполняет в своём кабинете (имя, телефон,
  марка/модель, гос. номер, заметки), одна строка на VIN (`vin` — первичный ключ). Хранится
  отдельно от `clients`, чтобы правки клиента не затирали карточку, которую ведёт админ, и
  потому что один и тот же VIN исторически может встречаться у нескольких строк `clients`
  (см. заметку про массовый импорт чек-листов в git-истории). Кабинет клиента показывает
  историю ремонта по всем строкам `clients` с этим VIN — не только по одной.
- **client_requests** — заявки из кабинета клиента: VIN, текст, опционально фото (base64 data
  URL), флаг прочтения. Видны владельцу во вкладке «Заявки».
- **staff_notes** — личные заметки владельца: текст, тег (`urgent`/`normal`), даты создания и
  правки. Вкладка «Заметки».
- **sessions** — активные сессии входа (владелец и клиенты по VIN), зеркало сессий из памяти
  процесса на диск — см. «Авторизация».

## API

Все пути, кроме перечисленных в разделе «Авторизация» как открытые, требуют активной сессии
владельца (401 без неё); пути `/api/client/*` вместо этого требуют клиентской сессии.

| Метод | Путь                                       | Описание                                   |
|-------|----------------------------------------------|----------------------------------------------|
| POST  | `/api/login`                                | Вход владельца (телефон + пароль)            |
| POST  | `/api/logout`                               | Выход владельца                              |
| GET   | `/api/session`                              | Проверить, авторизован ли владелец           |
| POST  | `/api/client-login`                         | Вход клиента (VIN, при неизвестном VIN — ещё и пароль-год) |
| POST  | `/api/client-logout`                        | Выход клиента                                |
| GET   | `/api/client-session`                       | Проверить, авторизован ли клиент             |
| GET   | `/api/client/me`                            | Анкета машины клиента + история ремонта      |
| PUT   | `/api/client/car`                           | Клиент сохраняет свою анкету (имя/телефон/машина, включая исправление VIN); для VIN не из базы — регистрация, админу создаётся заявка |
| GET   | `/api/client/requests`                      | Заявки, отправленные этим клиентом           |
| POST  | `/api/client/requests`                      | Отправить заявку (текст и/или фото)          |
| GET   | `/api/requests`                             | Все заявки клиентов (для владельца)          |
| PUT   | `/api/requests/:id/read`                    | Отметить заявку прочитанной                  |
| DELETE| `/api/requests/:id`                         | Удалить заявку                               |
| GET   | `/api/notes`                                | Список заметок владельца                     |
| POST  | `/api/notes`                                | Добавить заметку                             |
| PUT   | `/api/notes/:id`                            | Обновить заметку                             |
| DELETE| `/api/notes/:id`                            | Удалить заметку                              |
| GET   | `/api/clients`                              | Список клиентов                              |
| POST  | `/api/clients`                              | Создать клиента                              |
| PUT   | `/api/clients/:id`                          | Обновить клиента                             |
| DELETE| `/api/clients/:id`                          | Удалить клиента                              |
| GET   | `/api/clients/:id/repairs`                  | История ремонта клиента                      |
| POST  | `/api/clients/:id/repairs`                  | Добавить запись ремонта клиенту              |
| PUT   | `/api/repairs/:id`                          | Обновить запись ремонта                      |
| DELETE| `/api/repairs/:id`                          | Удалить запись ремонта                       |
| GET   | `/api/queue`                                | Список заказов «в очереди»                   |
| POST  | `/api/queue`                                | Создать заказ в очереди                      |
| PUT   | `/api/queue/:id`                            | Обновить заказ (в т.ч. статус)                |
| DELETE| `/api/queue/:id`                            | Удалить заказ из очереди                     |
| GET   | `/api/consumable-sections`                  | Список разделов расходников                  |
| POST  | `/api/consumable-sections`                  | Создать раздел                               |
| PUT   | `/api/consumable-sections/:id`              | Переименовать раздел                         |
| DELETE| `/api/consumable-sections/:id`              | Удалить раздел (и категории/расходники в нём)|
| GET   | `/api/consumable-categories`                | Список категорий расходников                 |
| POST  | `/api/consumable-categories`                | Создать категорию                            |
| PUT   | `/api/consumable-categories/:id`            | Переименовать категорию                      |
| DELETE| `/api/consumable-categories/:id`            | Удалить категорию (и расходники в ней)       |
| GET   | `/api/consumables`                          | Список расходников                           |
| POST  | `/api/consumables`                          | Создать расходник                            |
| PUT   | `/api/consumables/:id`                      | Обновить расходник                           |
| DELETE| `/api/consumables/:id`                      | Удалить расходник                            |
| GET   | `/api/reports?start=&end=`                  | Отчёт: записи ремонта в диапазоне дат, с тегом/маркой/моделью клиента |
| GET   | `/api/appointments?start=&end=`             | Записи в диапазоне дат (YYYY-MM-DD)          |
| POST  | `/api/appointments`                         | Создать запись                               |
| PUT   | `/api/appointments/:id`                     | Обновить запись                              |
| DELETE| `/api/appointments/:id`                     | Удалить запись                               |

## Дальнейшие идеи (не реализовано)

- Напоминания клиентам (SMS/e-mail) о записи.
- Журнал изменений (кто и когда редактировал запись) — сейчас пользователь один, это не критично.
