# ГУРсервис — учёт клиентов, записей и расходников автосервиса

Веб-приложение для одного автосервиса: расписание записей, база клиентов с историей ремонта,
очередь заказов на запчасти, заказ-наряды, справочник расходников и личный кабинет для клиентов
(вход по VIN). Рассчитано на одного владельца/администратора (авторизация по логину и паролю),
крутится на локальном сервере без внешних зависимостей.

## В двух словах

- **Расписание** — неделя, дни Пн–Сб, drag-and-drop записей, разовые визиты без базы.
- **Клиенты** — карточка с тегом для поиска, кликабельный телефон, копирование VIN одной
  кнопкой, история ремонта.
- **История ремонта** — работы и запчасти (артикул/фирма/кол-во, копирование артикула одной
  кнопкой), срок поставки, аванс. Кол-во у запчасти — информационное поле, на сумму не влияет
  (цена в строке — это цена всей позиции, а не цена за штуку).
- **Смета из расписания** — кнопка на записи ищет клиента по имени и предлагает дополнить
  существующий ремонт или создать новый; для разового визита клиент заводится автоматически.
- **Заказ-наряд** — оформленный документ (шапка с реквизитами, работы/запчасти, рекомендации),
  открывается на весь экран на телефоне; картинкой (PNG, рисуется на `<canvas>`) копируется сразу
  в буфер обмена — вставить в мессенджер можно без скачивания файла.
- **Заказы** («в очереди») — клиенты, которым заказаны запчасти. У каждой запчасти свой
  флаг «на складе» и выбор поставщика (АТС / ПЛ / emex / Микадо); общий статус заказа
  («в ожидании» / «запчасти пришли») считается автоматически по этим флагам, пока в заказе есть
  хоть одна запчасть. Нового клиента для заказа можно подтянуть из базы вместо ручного ввода.
  В общую базу клиентов заказ попадает только по кнопке «Добавить в список клиентов».
- **Расходники** — двухуровневая структура: разделы → категории → позиции с артикулами
  (копирование одной кнопкой) для регулярно заказываемых материалов.
- **Кабинет клиента** — отдельный вход по VIN автомобиля (см. ниже). Клиент видит и сам
  дополняет данные своей машины (имя, телефон, марка/модель, гос. номер, заметки) и историю
  выполненных работ (только чтение), может отправить заявку в сервис — текст и/или фото.
- **Заявки** — входящие сообщения из кабинета клиента, отдельная вкладка у владельца с бейджем
  непрочитанных. Если VIN не найден среди клиентов, карточка заявки предлагает кнопку
  «Добавить клиента» — она открывает диалог нового клиента с уже подставленными VIN и всеми
  данными, которые клиент успел ввести в своём кабинете (даже если он не нажимал отдельную
  кнопку «Сохранить» — анкета сохраняется автоматически при отправке заявки).
- Строгие маски ввода: телефон — только цифры, всегда с `+7`; марка/модель — только английские
  буквы, каждое слово с заглавной буквы; гос. номер — формат `Б999ББ999` (буква-цифры-2 буквы-
  цифры), буквы только из набора, разрешённого ГОСТом для рос. знаков, с автозаменой похожих
  латинских букв на кириллические.
- Подтверждения удаления и закрытия окна кликом мимо — свой стилизованный диалог, не системный
  `window.confirm`.
- Всё в одном общем аккаунте — данные видит и правит один и тот же авторизованный владелец.

## Стек

- **Backend:** Node.js (встроенный `http`, без Express) + встроенный `node:sqlite` — **нет ни
  одной внешней зависимости**, `npm install` не нужен.
- **Frontend:** обычные HTML/CSS/JS, без сборщиков и фреймворков.
- **Требование:** Node.js **22.5+** (нужен для `node:sqlite`). Проверить версию: `node --version`.

## Запуск локально

```bash
node server.js
```

Откройте http://localhost:3000 — сайт сразу покажет экран входа.

При первом запуске автоматически создастся файл `autoservice.db` (SQLite) со всеми таблицами —
ничего дополнительно настраивать не нужно. При обновлении версии приложения на уже существующей
базе миграции колонок/таблиц применяются автоматически при старте сервера.

Порт можно поменять переменной окружения:

```bash
PORT=8080 node server.js
```

## Авторизация

Два независимых входа с отдельными cookie-сессиями, обе хранятся в памяти процесса (30 дней;
перезапуск сервера разлогинивает всех):

- **Владелец** — телефон + пароль, заданы константами `OWNER_PHONE`/`OWNER_PASSWORD` в начале
  `server.js`. Без входа всё API, кроме путей ниже, отдаёт 401, фронтенд показывает форму входа.
- **Клиент** — вход только по VIN автомобиля (до 17 символов):
  - если VIN найден среди клиентов — вход сразу успешен;
  - если не найден — просит пароль, чтобы отсечь спам-ботов. Пароль равен текущему году
    (считается на сервере функцией `currentYearPassword()`, автоматически меняется 1 января).
  - После входа клиент видит только свой кабинет (`/api/client/*`), не владельческие данные.

Пути `/api/login`, `/api/logout`, `/api/session`, `/api/client-login`, `/api/client-logout`,
`/api/client-session` не требуют авторизации (это и есть вход). `/api/client/*` проверяют
клиентскую сессию (не владельческую) — своя, более узкая проверка прямо в обработчике каждого
пути. Всё остальное API закрыто владельческой сессией и без неё отдаёт 401.

## Основные сущности

- **clients** — клиенты: имя, телефон, марка/модель, гос. номер, тег, VIN, заметки.
- **appointments** — записи в расписании; либо привязаны к клиенту (`client_id`), либо это
  разовый визит (поля `walkin_*`), который в базу клиентов не попадает.
- **repair_records** — история ремонта клиента: заголовок, дата, работы/запчасти (JSON:
  `[{name, price, article?, brand?, qty?}]`), срок поставки запчастей, аванс, рекомендации.
- **queue_entries** — заказы «в очереди»: те же поля, что у клиента, плюс смета и статус
  (`waiting` / `arrived` — на фронтенде пересчитывается автоматически по запчастям, если они
  есть). У запчастей в JSON дополнительно `received` (флаг «на складе») и `supplier`
  (АТС/ПЛ/emex/Микадо) — эти два поля используются только на странице заказов. Превращаются
  в настоящего клиента вручную, кнопкой «Добавить в список клиентов».
- **consumable_sections** → **consumable_categories** → **consumables** — двухуровневая
  структура расходников (раздел → категория → позиция с артикулом); категория может быть без
  раздела, расходник может быть без категории — пользователь заводит всё сам, ничего не
  предустановлено.
- **client_car_profiles** — анкета, которую клиент сам заполняет в своём кабинете (имя, телефон,
  марка/модель, гос. номер, заметки), одна строка на VIN (`vin` — первичный ключ). Хранится
  отдельно от `clients`, чтобы правки клиента не затирали карточку, которую ведёт админ, и
  потому что один и тот же VIN исторически может встречаться у нескольких строк `clients`
  (см. заметку про массовый импорт чек-листов в git-истории). Кабинет клиента показывает
  историю ремонта по всем строкам `clients` с этим VIN — не только по одной.
- **client_requests** — заявки из кабинета клиента: VIN, текст, опционально фото (base64 data
  URL), флаг прочтения. Видны владельцу во вкладке «Заявки».

## API

Все пути, кроме перечисленных в разделе «Авторизация» как открытые, требуют активной сессии
владельца (401 без неё); пути `/api/client/*` вместо этого требуют клиентской сессии.

| Метод | Путь                                       | Описание                                   |
|-------|----------------------------------------------|----------------------------------------------|
| POST  | `/api/login`                                | Вход владельца (телефон + пароль)            |
| POST  | `/api/logout`                               | Выход владельца                              |
| GET   | `/api/session`                              | Проверить, авторизован ли владелец           |
| POST  | `/api/client-login`                         | Вход клиента (VIN, при неизвестном VIN — ещё и пароль-год) |
| POST  | `/api/client-logout`                        | Выход клиента                                |
| GET   | `/api/client-session`                       | Проверить, авторизован ли клиент             |
| GET   | `/api/client/me`                            | Анкета машины клиента + история ремонта      |
| PUT   | `/api/client/car`                           | Клиент сохраняет свою анкету (имя/телефон/машина) |
| GET   | `/api/client/requests`                      | Заявки, отправленные этим клиентом           |
| POST  | `/api/client/requests`                      | Отправить заявку (текст и/или фото)          |
| GET   | `/api/requests`                             | Все заявки клиентов (для владельца)          |
| PUT   | `/api/requests/:id/read`                    | Отметить заявку прочитанной                  |
| DELETE| `/api/requests/:id`                         | Удалить заявку                               |
| GET   | `/api/clients`                              | Список клиентов                              |
| POST  | `/api/clients`                              | Создать клиента                              |
| PUT   | `/api/clients/:id`                          | Обновить клиента                             |
| DELETE| `/api/clients/:id`                          | Удалить клиента                              |
| GET   | `/api/clients/:id/repairs`                  | История ремонта клиента                      |
| POST  | `/api/clients/:id/repairs`                  | Добавить запись ремонта клиенту              |
| PUT   | `/api/repairs/:id`                          | Обновить запись ремонта                      |
| DELETE| `/api/repairs/:id`                          | Удалить запись ремонта                       |
| GET   | `/api/queue`                                | Список заказов «в очереди»                   |
| POST  | `/api/queue`                                | Создать заказ в очереди                      |
| PUT   | `/api/queue/:id`                            | Обновить заказ (в т.ч. статус)                |
| DELETE| `/api/queue/:id`                            | Удалить заказ из очереди                     |
| GET   | `/api/consumable-sections`                  | Список разделов расходников                  |
| POST  | `/api/consumable-sections`                  | Создать раздел                               |
| PUT   | `/api/consumable-sections/:id`              | Переименовать раздел                         |
| DELETE| `/api/consumable-sections/:id`              | Удалить раздел (и категории/расходники в нём)|
| GET   | `/api/consumable-categories`                | Список категорий расходников                 |
| POST  | `/api/consumable-categories`                | Создать категорию                            |
| PUT   | `/api/consumable-categories/:id`            | Переименовать категорию                      |
| DELETE| `/api/consumable-categories/:id`            | Удалить категорию (и расходники в ней)       |
| GET   | `/api/consumables`                          | Список расходников                           |
| POST  | `/api/consumables`                          | Создать расходник                            |
| PUT   | `/api/consumables/:id`                      | Обновить расходник                           |
| DELETE| `/api/consumables/:id`                      | Удалить расходник                            |
| GET   | `/api/appointments?start=&end=`             | Записи в диапазоне дат (YYYY-MM-DD)          |
| POST  | `/api/appointments`                         | Создать запись                               |
| PUT   | `/api/appointments/:id`                     | Обновить запись                              |
| DELETE| `/api/appointments/:id`                     | Удалить запись                               |

## Дальнейшие идеи (не реализовано)

- Напоминания клиентам (SMS/e-mail) о записи.
- Журнал изменений (кто и когда редактировал запись) — сейчас пользователь один, это не критично.
